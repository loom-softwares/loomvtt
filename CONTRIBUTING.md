# Contributing to LoomVTT (Issue Tracker)

Thank you for taking the time to report a bug or suggest a feature! This guide will help you write clear, actionable reports so we can help you faster.

> ℹ️ **This repo is an issue tracker only.** It contains no source code. If you're looking to build addons or systems for LoomVTT, check the SDK documentation.

---

## 📋 Before You Open an Issue

1. **Search first** — Check [existing issues](../../issues) (open and closed) to avoid duplicates.
2. **Use the right template** — Each issue type has a dedicated form. Blank issues are disabled.
3. **Be specific** — Vague reports are hard to act on. The more detail, the better.

---

## 🐛 Writing a Good Bug Report

A great bug report answers:

- **What happened?** Describe the actual behavior.
- **What did you expect?** Describe the expected behavior.
- **How do I reproduce it?** Provide exact steps. If we can't reproduce it, we can't fix it.
- **What's your setup?** Include your LoomVTT version, OS, and browser/client.

**Screenshots and logs are extremely helpful.** Drag and drop them directly into the issue form.

---

## ✨ Writing a Good Feature Request

A great feature request answers:

- **What problem does it solve?** Describe the frustration or gap, not just the solution.
- **What's your proposed solution?** Be as specific as you can.
- **Are there alternatives?** Mention any workarounds you've tried.

---

## 🏷️ Labels

Issues are triaged with the following labels:

| Label | Meaning |
|-------|---------|
| `bug` | Confirmed misbehavior |
| `enhancement` | New feature or improvement |
| `performance` | Speed, memory, or rendering issue |
| `documentation` | Missing or incorrect docs |
| `question` | General question, may be closed after response |
| `wontfix` | Acknowledged but won't be addressed |
| `duplicate` | Covered by another issue |
| `needs-info` | Waiting on more information from reporter |

---

## ⏱️ What Happens After You Submit?

1. **Triage** — We review and label the issue, usually within a few days.
2. **Needs Info?** — If we need more details, we'll add `needs-info` and ask. Issues without a response after 14 days may be closed.
3. **In Progress** — Issues being worked on will be linked to a milestone.
4. **Done** — Fixed issues are closed with a reference to the changelog entry.

---

## 🔒 Security Issues

**Do not open public issues for security vulnerabilities.**
See [SECURITY.md](./SECURITY.md) for responsible disclosure.
